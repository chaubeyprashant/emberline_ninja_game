## 0. Shared facts (apply to every enemy row; kept out of the table to keep cells readable)

- **Body pipeline**: `EnemyKind` (`Assets/Scripts/Enemies/EnemyBrain.cs:8-9`, 13 values, append-only, serialised by index) → hand-written table in `BuildEnemyPrefabs()` (`Assets/Editor/EmberlineBootstrap.cs:1156-1225`) → `SkeletalEnemyPrefab(kind, name, EmberCharacterFactory.<Spec>(), hp, spd, range, dmg, windup, spawn, weapon)` (`:1583-1613`) → `EmberCharacterFactory.Build(root, spec)` (`Assets/Editor/EmberCharacterFactory.cs:624-718`) → `PrefabUtility.SaveAsPrefabAsset(root, "Assets/Prefabs/<Name>.prefab")` (`:1609-1610`) → `AssignEnemyDefs` binds `EnemyBrain.def` (`:1557-1579`) → `BuildScene` stores the array on `GameManager.enemyPrefabs` (`:166`), serialised by GUID in `Assets/Scenes/Rooftop.unity:2882` and `Assets/Scenes/Marsh.unity:3283` (both verified to be exactly `Bandit RangedWeaver BanditChief Shade Kagachi Jin RaiderAxe PikeGuard Bomber Assassin Samurai RogueNinja EliteWarrior`, i.e. EnemyKind order). `Opening.unity` has no GameManager.
- **Runtime spawn (all kinds)**: `GameManager.enemyPrefabs[(int)kind]` is the only body source (`Assets/Scripts/GameManager.cs:18`). Entry points: `SpawnWave` `:582` → `EnemyPool.Spawn` `:607`; `SpawnOne` `:825-845` (prefab `:827-828`, spawn `:839`); `SpawnNamed` `:851-875` (prefab `:853-854`, spawn `:864`, `SetDef` `:867-868`); `SpawnRunEnemy` `:899-` (prefab `:901-902`, spawn `:904`). `EnemyPool.Spawn` instantiates on a miss (`Assets/Scripts/Enemies/EnemyPool.cs:39`), else `ResetForSpawn()` + `SetActive(true)` (`:48-49`). Callers: `MissionDirector.cs:254` (`SpawnOne`), `:262-264` (`SpawnNamed`, kind = `def.kind`), `EndlessDirector.cs:177,210`, debug drivers `CombatTestArena.cs:29-33`, `CombatScenarioDriver.cs:100-101`.
- **Rig type (all 13 enemy bodies)**: KayKit FBX, `ModelImporter.animationType = 2 (Generic)`, `avatarSetup = 0`, clip library embedded in the same FBX (forced Generic by `Assets/Editor/EmberArtImport.cs:84`). Verified on all 9 KayKit `.fbx.meta`.
- **Avatar (all 13)**: none. `Build()` copies an `Avatar` sub-asset only if the FBX has one (`EmberCharacterFactory.cs:691-693`); KayKit has none; every enemy prefab serialises `m_Avatar: {fileID: 0}` (verified on all 13).
- **Animator controller**: `Assets/Prefabs/Characters/Anim_<spec.name>.controller`, regenerated by `BuildController` (`:941-986`, path `:944`, deleted+recreated each build `:945-946`). Params `Move`, `AtkSpeed` (`:947-948`); default state `Locomotion` = 1D blend tree Idle(0)/Run(1) on `Move` (`:959-972`); one state per other `RigPose`, named `pose.ToString()`, `speedParameter = AtkSpeed` (`:975-984`); unmapped/missing clips fall back to the `Idle` clip (`:952-956`). `RigPose` has 23 values (`Assets/Scripts/Core/NinjaRig.cs:12-26`) → 22 states per controller. Verified: each enemy prefab's Animator references its own `Anim_<spec.name>` controller.
- **Material / texture**: `Assets/Prefabs/Characters/Mat_<spec.name>.mat` on every renderer (`:671-682`; `CharacterMaterial` `:720-750`, shader `SurfaceKit.SurfaceShader` = `Assets/Shaders/EmberSurface.shader`, `SurfaceKit.Apply(mat, Surface.Cloth, white)` `:746`); `_MainTex` = `Tex_<spec.name>.png` written by `RecoloredTexture` (`:753-782`, 512×512, uncompressed, no mips, from the KayKit 1024² palette). Ghost specs use `Emberline/Ghost` (`Assets/Shaders/EmberGhost.shader`) with `mat.color = (tint.rgb, ghostAlpha)` (`:727`, `:738-741`). Props share `Mat_Prop.mat` (`:896-908`, Surface.Steel).
- **Height**: `spec.height`; model `localScale = height / union(SkinnedMeshRenderer.bounds).size.y` (`:643-650`), stored as `VisualRoot.normalisedHeight` (`:651`). Verified equal to `normalisedHeight` in every prefab. `EnemyDef.scale` is never read (see §2 and §3).
- **Hierarchy**: root `<Name>` = `SkeletalRig` (`:700-716`) + `EnemyBrain` (`Bootstrap:1598-1607`); child `VisualRoot` = FBX instance + `VisualRoot` component (`modelId = spec.name`, sockets, height; `:637-640`, `:695-696`) + `Animator`; embedded meshes under any transform containing `handslot` are disabled unless named in `keepEmbedded` (`:655-664`); props instantiated as `Prop_<prop>_<r|l>` under the resolved socket (`:856-894`); `TrailRenderer` child `Trail` only when `trail && side=="r"` **and** a right prop exists (`:860`, `:881-893`).
- **Base defs**: `Assets/Resources/Enemies/<File>.asset`, authored in `AssignEnemyDefs` (`Bootstrap:1234-1581`), found at runtime by `EnemyDefs.Find(id)` (`Assets/Scripts/Enemies/EnemyDef.cs:201-216`). `EnemyBrain.SetDef/ApplyDef` (`EnemyBrain.cs:340-359`) copies only `kind, weapon, maxHp, moveSpeed, attackRange, damage, windupTime, spawnTime` — nothing visual.
- **Named foes**: `Named(id, baseDef, …)` (`Bootstrap:1523-1537`) = `EditorUtility.CopySerialized(baseDef, d)` (`:1527`) + id/display/rank/hp×/dmg×/posture×1.5/title/taunt. They inherit `kind`, `modelSpec`, `scale` and even `m_Name` from the base. **No prefab of their own**; they are spawned on the base kind's prefab (`SpawnNamed` or the duel path `GameManager.cs:608-613`). Kits/personalities: `EmberCombatKits.ApplyNamed()` (`Assets/Editor/EmberCombatKits.cs:200-250`), visual-free.

Clip-table shorthand: **OH** = `OneHanded()` (`EmberCharacterFactory.cs:104-130`: Idle=Idle, Run=Running_A, Strike1=1H_Melee_Attack_Slice_Diagonal, Strike2=1H_Melee_Attack_Slice_Horizontal, Strike3=1H_Melee_Attack_Chop, Cleave=2H_Melee_Attack_Spinning, Windup=Spellcast_Raise, Hurt=Hit_A, Dash=Dodge_Forward, Dead=Death_A, Spawn=Spawn_Ground, Taunt=Cheer, Stab=1H_Melee_Attack_Stab, Sweep=1H_Melee_Attack_Slice_Horizontal, Block=Blocking, BlockHit=Block_Hit, SideStep=Dodge_Left, Backstep=Dodge_Backward, Kick=Unarmed_Melee_Attack_Kick, Throw=Throw, Jump=Jump_Full_Short, Charge=Running_A, Delayed=Spellcast_Long). **2H** = `TwoHandedCombatClips` (`:133-137`: Stab=2H_Melee_Attack_Stab, Sweep=2H_Melee_Attack_Spin). **DW** = `DualWieldCombatClips` (`:140-144`: Stab=Dualwield_Melee_Attack_Stab, Sweep=Dualwield_Melee_Attack_Slice). Overrides are applied in source order.

## 2. Contradictions between reports and how they were settled

1. **Spec method count** — `specs` report header says "SPEC METHODS — 24 total", its own summary says 22. Source: `grep "public static Spec"` returns **22** methods = 21 spec constructors + the `PlayerSpec()` switch (:215). 13 of the 21 are enemy specs, 8 are player/story cast. Settled: 22 / 21 / 13.
2. **Where `RigPose` lives** — `spawn` says `Assets/Scripts/Core/NinjaRig.cs:12-26`; `duel-bosses` says `Assets/Scripts/Core/CharacterRig.cs`. Source: the enum is at `NinjaRig.cs:12-26` (23 values). `CharacterRig.cs:13-45` is the abstract rig API only. Settled: NinjaRig.cs.
3. **Avatar on enemy bodies** — `kind-to-spec` says "Animator + generated controller … humanoid avatar bound (691-693)"; `assets` says KayKit is Generic with `avatarSetup 0` and `Shade.prefab` has `m_Avatar: {fileID: 0}`. Source: `Build()` copies an Avatar only `if (srcAvatar != null)` (:691-693); all 9 KayKit `.fbx.meta` have `animationType: 2`, `avatarSetup: 0`; all 13 enemy prefabs serialise `m_Avatar: {fileID: 0}`. Settled: **enemies are Generic rigs with no avatar**; only `MixamoNinja.fbx` (player) is Humanoid.
4. **Assassin's weapons** — `duel-bosses` lists only `propRight dagger`; `specs` lists `propRight="dagger"` and `propLeft="dagger"`. Source :525-526 sets both; `Assassin.prefab` nests the dagger FBX. Settled: two daggers (only spec with a left prop).
5. **Spec line ranges** — `duel-bosses` gives Samurai `:534-556` and Assassin `:511-533`; `spawn` gives `534-555` / `511-531`. Source: Samurai ends at 555, Assassin at 531. Settled in favour of `spawn`.
6. **`PlayerSpec()` line** — `specs` says 215, `assets` says 216. Source: 215.
7. **Height normalisation range** — `kind-to-spec` 643-651 vs `duel-bosses` 642-651. Source: 642 is the comment, code 643-650, `normalisedHeight` at 651. Immaterial; table uses 643-651.
8. **`EnemyKind` enum line** — `kind-to-spec` 7-9 vs `spawn` 8-9. Source: comment at 7, enum at 8-9.
9. **Named-foe count vs duel count** — `kind-to-spec` lists 7 named foes; `duel-bosses` covers only the 6 that appear in duels. Source: `raiderleader` is authored (`:1540-1541`) but has no `DuelDef`; it is spawned only from the campaign (`CampaignTable.cs:197`). Settled: 7 named foes, 6 of them duelists.
10. **"Kagachi-specific runtime hooks" in `duel-bosses`** bundles the enrage tints at `EnemyBrain.cs:988/993` under Kagachi. ## 3. What a visual-only replacement MUST preserve

Fields on `EmberCharacterFactory.Spec` and runtime contracts that gameplay/UI actually reads:

1. **`Spec.name`** — becomes `VisualRoot.modelId` (`:640`) and names the regenerated `Anim_/Mat_/Tex_<name>` assets (`:944`, `:723`, `:756`). `EnemyDef.modelSpec` matches it by convention only (inert), but keep it in sync so the def assets stay truthful. `EmberSnapshot.cs:38-54` enumerates specs with a hard-coded KayKit clip name each; update it if clip names change.
2. **`Spec.height`** — the only body scale that exists at runtime (`:643-651`; `EnemyDef.scale` is dead). Keep 1.72 / 1.7 / 2.45 / 1.62 / 2.1 / 1.85 / 1.95 / 1.9 / 1.7 / 1.74 / 1.92 / 1.78 / 2.2 unless the intent is to re-read silhouettes; the cinematic camera looks at `focus + 1.35 m` fixed (`CameraRig.cs:228`, `:205`), attack ranges are on the def, so height changes affect readability, not hit logic.
3. **Clip map coverage (`Spec.clips`)** — every `RigPose` the brain drives must resolve in the clip library (`Clips(spec)` = model FBX ∪ `clipSources`, `:918-939`); unmapped poses silently fall back to Idle (`:952-956`). Poses actually driven: Spawn scrubbed by phase (`EnemyBrain.cs:499`), Dead scrubbed (`:832`), Taunt one-shots (`:174, :997, :1019`; `BossIntroDirector.cs:42`), plus Strike1-3/Cleave/Windup/Hurt/Dash/Stab/Sweep/Block/BlockHit/SideStep/Backstep/Kick/Throw/Jump/Charge/Delayed via attack kits. `SkeletalRig.poseClipLengths` (`:707-716`) feeds `AtkSpeed = clipLen/duration` (`SkeletalRig.cs:66-76`), so clip lengths must be sane.
4. **Animator contract** — controller must have float params `Move`, `AtkSpeed`, default state `Locomotion`, and one state per pose named exactly `RigPose.ToString()`, all on layer 0 (`SkeletalRig.cs:24-26`, `:76`, `:170`, `:178`, `:201-213`). Regenerating through `BuildController` satisfies this automatically; a hand-authored controller must match. One `Animator` under `VisualRoot` (found by `GetComponentInChildren<Animator>()` `SkeletalRig.cs:53`); `applyRootMotion=false` (`:688`). A Humanoid replacement needs an Avatar sub-asset (`:691-693`) and `optimizeGameObjects=false` (`EmberArtImport.cs:79`) so bone transforms exist for sockets.
5. **Sockets** — `propRight` needs a right-hand socket (all except Bandit/Goro/Jin/Shade), `propLeft` a left one (Assassin). Resolution order `:821-848`: declared `socketRight/socketLeft` names — a match is returned as-is only when its name contains `handslot`; any other declared bone (e.g. `mixamorig:RightHand`) is wrapped in a `GripAnchor_<side>` child carrying `propOffsetPos/Rot` (`:833`) → transform name containing `handslot.r`/`handslotr` → `hand.r`/`handr`/`*righthand`, likewise wrapped in `GripAnchor_<side>` (`GripAnchor` `:804-819`; the left side mirrors pos.x and rot.y/z). At audit time only `MixamoRenzo()` (player) declares sockets, so it is the only body on the declared→GripAnchor path; every KayKit enemy resolves through its `handslot` empties with no anchor. Results are stored on `VisualRoot.socketRight/Left` (`:695-696`).
6. **Embedded weapons (`keepEmbedded`)** — every `MeshRenderer` under a transform whose name contains `handslot` is disabled unless its GameObject name is listed (`:655-664`). Bandit `{Knife, Knife_Offhand}`, Goro `{2H_Axe}`, Jin `{2H_Sword}` currently rely on this; a replacement must either ship the weapon as a `propRight` FBX in `Assets/Art/Characters/Props/` (with offsets) or keep the same embedded naming.
7. **Trail** — `trail=true` (Kagachi, Samurai, EliteWarrior; Jin nominal) creates a `TrailRenderer` child `Trail` at local (0,0.55,0) on the **right prop only** (`:881-893`); `SkeletalRig` finds it by `GetComponentInChildren<TrailRenderer>(true)` (`SkeletalRig.cs:57`). A replacement whose blade is embedded needs its own child TrailRenderer or the trail is lost.
8. **Material behaviour** — `materialMode`: `PaletteOverride` forces `Mat_<name>` onto every renderer slot (`:671-680`); `KeepAuthored` keeps FBX materials. Whatever shader ends up on the body must accept `_Color` via `MaterialPropertyBlock` (`SkeletalRig.cs:217-224`): used by `SetBaseColor` enrage tints (Goro `EnemyBrain.cs:993`, Jin `:988`), `Flash`, `SetMood`, and the ghost alpha. Ghosting replaces **every** `sharedMaterials` slot with a shared `Emberline/Ghost` material and turns shadow casting off (`SkeletalRig.cs:227-244`) — applied at build for Shade (`ghost=true`) and at runtime to Kagachi clones (`MakeGhost(0.45f)` `EnemyBrain.cs:1046`). After-images `BakeMesh` every `SkinnedMeshRenderer` (`SkeletalRig.cs:323`), so the body must be skinned meshes, not static MeshRenderers.
9. **Shade tint/ghost fields** — `tint (0.55,0.72,0.88)`, `ghost=true`, `ghostAlpha=0.55` are copied to `SkeletalRig` (`:701-703`) and applied in `Awake` (`SkeletalRig.cs:58-59`); `paleshade` inherits the look.
10. **Component layout and names** — `SkeletalRig` + `EnemyBrain` on the root, visual under a single child named `VisualRoot` (`:637`). `EnemyBrain` addresses the rig only through `GetComponent<CharacterRig>()` (`EnemyBrain.cs:363`) and never by name/`transform.Find` (grep clean). `Prop_` name conventions are only read on the player (`CombatController.cs:239-253`, `Cosmetics.cs:102`).
11. **Identity keyed by `EnemyKind` and prefab path** — the scenes reference `Assets/Prefabs/<Name>.prefab` by GUID in EnemyKind order (`Rooftop.unity:2882`, `Marsh.unity:3283`). Rebuild through `SetupScenes`/`BuildEnemyPrefabs` so `SaveAsPrefabAsset` lands on the same path/GUID, the same `name` (`Bandit, RangedWeaver, BanditChief, Shade, Kagachi, Jin, RaiderAxe, PikeGuard, Bomber, Assassin, Samurai, RogueNinja, EliteWarrior`), and `Bind` re-attaches `EnemyBrain.def` (`:1557-1579`). Do not reorder or rename `EnemyKind`.
12. **`EnemyBrain.kind` / `weapon` serialised on the prefab** (`Bootstrap:1598-1600`) — read by the HUD (`EmberHud.cs:684-707` `KindWeapon/KindName`, boss bar `:1816`), boss intro matching `e.kind == bossKind` (`GameManager.cs:654-686`, `:677`), named intro matching `def.displayName` (`:691-704`, `:696`), `BossIntroDirector` weapon headline/glyph (`BossIntroDirector.cs:116-132`), `Session.BossCard(kind)` (`Session.cs:349`), `StoryMemory.Lore(kind)` (`StoryMemory.cs:42`). A model swap must not change these values.
13. **Def assets, kits, profiles** (`Resources/Enemies/*.asset`, `Resources/Combat/Profile_*.asset`) are untouched by a model swap as long as `Bind` runs; named foes need no visual work at all (they ride the base prefab). `EmberDuelIntegrity.cs:37-41` checks only that a def resolves per duel.
14. **Kagachi clone survivability** — the whole live GameObject is `Instantiate`d twice (`EnemyBrain.cs:1041`); the visual must survive duplication (no scene-unique references, no runtime-only bindings) and the material swap in (8).
